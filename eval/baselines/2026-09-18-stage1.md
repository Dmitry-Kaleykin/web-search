# Stage 1 retrieval baseline — 18 September 2026

This records retrieval behavior, not answer accuracy or research stopping quality. No model or
paid search API was called by the baseline. The active interface remains `web_search` / `read_url`.

## Before the changes

The assessment in this task established these failures:

- A fresh Python documentation read failed because DNS returned `198.18.0.44` and local fake-IP
  proxy compatibility was disabled. A process-local opt-in made the read succeed.
- Extracted Markdown incorrectly linked to `https://docs.python.org/asyncio-exceptions.html`
  instead of retaining `/3/library/`. Structured HTML links were correct.
- A deterministic reproduction of an engine timeout showed its warning disappearing on a cache
  hit once the engine cooldown expired. The cached result had no exposed original retrieval time.
- The readiness doctor checked installed components and search, but did not attempt a public read.

These observations were made during the preceding assessment, not by replaying an old version
against today's changing web. They are now covered by local regression checks.

## Limits and next comparison

The baseline does not measure broad web recall, independent corroboration, citation support,
answer quality, or appropriate stopping. Those belong to Stage 2. It deliberately retains upstream
failures and does not retry until a report passes. Re-run the same manifest under a new filename
for future comparisons, preserve both reports, and review source relevance separately from
transport success.

Restart/reconnect the MCP server to load the code and refreshed output schema. Existing cursors
continue their original immutable snapshots; start a new read to receive corrected extraction.
